# 为什么医疗对话要“逐字整理”而不是“概括改写”

## 医疗文本的特殊性

- 症状的部位、持续时间、诱因、缓解方式，药物的名称、剂量、频次，都可能改变临床判断。概括时丢掉一个限定词（如“偶尔”“饭后”“左侧”），信息含义就会变化。
- 患者原话中的不确定表达（“好像”“有时候”“记不清”）本身也是信息，改写为确定语气会造成事实性偏差。
- 因此本 Skill 的目标是**结构化**，不是**摘要化**：把对话拆成问答、补上行号、标出缺口，但不改变原意和原文。

## 逐字保留与可追溯

- 每个问答对保留原文行号，读者可以回到源文件核对。
- 核验脚本检查“输出文本是否是原文的子串”，这是一条可自动执行的硬约束：只要模型或脚本添加了原文没有的内容，检查就会失败。
- 这比“让模型自己保证没有编造”更可核查。

## 与摘要式整理的区别

| 维度 | 本 Skill（结构化整理） | 摘要式整理 |
|---|---|---|
| 目标 | 保留原话，形成问答记录 | 压缩信息，提炼要点 |
| 文本改动 | 仅去时间戳和说话人标签 | 改写、合并、概括 |
| 可追溯性 | 逐条对应原文行号 | 通常无法逐句对应 |
| 适用 | 病历记录、教学复盘、质控抽查 | 快速了解对话大意 |
| 风险 | 输出较长、口语重复保留 | 易丢失限定词、改变语气 |

## 适用边界

- 本 Skill 不提供诊断、用药或随访建议；这些内容只能来自原始对话中的医生发言，且必须原样保留。
- 如果用户要求“帮我判断这个患者是什么病”，应说明这超出整理范围，并建议由有资质的医务人员判断。
- 涉及真实患者信息时，应先脱敏（姓名、身份证号、电话、住址等）；本 Skill 不做自动脱敏，需在输入前处理或在结果中人工复核。
