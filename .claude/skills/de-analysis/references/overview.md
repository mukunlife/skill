# 方法背景与适用边界

## counts 与 normalized 的区别

- **原始 counts**：RNA-seq 比对后每个基因的 reads 数，受测序深度和基因长度影响。直接比较不同样本的 counts 会引入系统偏差，因此先做 CPM（counts per million）归一化，再取 `log2(CPM + 1)` 压缩动态范围。
- **归一化表达**：芯片强度、TPM/FPKM 或已取 log 的矩阵。若仍是线性强度，取 `log2(x + 1)`；若已经是 log 尺度，直接使用，避免二次取对数。

本 Skill 用启发式规则自动判断（见 `rules.md`），并允许 `--data-type` 覆盖。判断依据和结果都会写入 `analysis_config.json`，便于复核。

## Welch t 检验

对每个基因分别比较两组的 log 表达均值：

```text
t = (mean_b - mean_a) / sqrt(s_a^2/n_a + s_b^2/n_b)
```

- 不要求两组方差相等，适合样本量小、方差不齐的两组比较。
- 双侧检验，零假设为两组均值相等。
- 对零方差基因需要单独处理，否则会出现 NaN 或无穷大的检验统计量。

## Benjamini-Hochberg 校正

对 m 个基因的 P 值排序后计算：

```text
padj_(i) = min_{j >= i} ( p_(j) * m / j )
```

BH 控制的是错误发现率（FDR），比 Bonferroni 更适合高通量筛选。`padj` 不是“该基因为真的概率”，报告时不能这样解释。

## 与 DESeq2 / edgeR 的差异

- DESeq2/edgeR 使用负二项分布建模 counts 的均值-方差关系，并通过经验贝叶斯方法收缩离散度，小样本时更稳健。
- 本 Skill 在 log2 CPM 上做 Welch t 检验，属于简化做法；样本量小、counts 离散度大或存在大量低表达基因时，P 值可能偏乐观或偏保守。
- 因此本 Skill 适合课堂练习、快速探索和流程演示；正式发表级分析应改用 DESeq2/edgeR 并报告版本与参数。

## 火山图

- 横轴：`log2FoldChange`，越远离 0 表示组间倍数差异越大。
- 纵轴：`-log10(padj)`，越高表示校正后显著性越强。
- 颜色：上调（红）、下调（蓝）、不显著（灰）；虚线为阈值。
- 火山图只展示显著性与效应量，不展示表达丰度；极低表达基因的差异需结合 `base_mean` 判断。

## 适用边界

| 场景 | 是否适用 | 说明 |
|---|---|---|
| 两组独立样本 | 是 | 默认流程 |
| 三组及以上 | 否 | 需 ANOVA 或多重比较 |
| 配对样本 | 否 | 应使用配对检验 |
| 单细胞数据 | 否 | 需专门的稀疏数据方法 |
| 每组 n < 3 | 谨慎 | 可运行，但统计功效低，结论只能作探索 |
